================================================================================
         PAYSTREAM BANKING PLATFORM — COMPLETE A-Z DEPLOYMENT GUIDE
                    MNC + Product Company Level Setup
================================================================================

  This guide builds ONE shared CI/CD pipeline that builds, scans, and
  deploys all 14 PayStream microservices (config-server, discovery-server,
  api-gateway, auth-service, customer-service, account-service, neft-service,
  rtgs-service, imps-service, upi-service, transaction-service,
  fraud-detection-service, notification-service, audit-service) using:
    - ONE Jenkinsfile / GitHub Actions workflow that loops/matrices over
      all 14 services for Docker build + Trivy scan + ECR push.
    - ONE generic Helm chart (helm/paystream-service/) parameterized per
      service (values/<service>.yaml) and per environment.
    - ONE ArgoCD ApplicationSet per environment (k8s/argocd/*.yaml) that
      generates one Application per service from that same chart.

TOOLS USED
----------
  Jenkins       — CI Pipeline (Build, Test, Scan, Push)
  SonarQube     — Code Quality + Quality Gate
  OWASP         — Dependency vulnerability scan
  Nexus         — Artifact repository (JAR storage)
  Trivy         — Docker image security scan
  AWS ECR       — Container image registry
  Terraform     — Infrastructure as Code (EC2 + EKS + ECR + VPC)
  Helm          — Kubernetes package manager
  ArgoCD        — GitOps CD (watches Git, deploys to K8s)
  Argo Rollouts — Canary deployment (20% → 50% → 100%)
  Istio         — Service mesh (mTLS + traffic control)
  Ext Secrets   — Pulls secrets from AWS Secrets Manager into K8s
  Cluster CA    — Scales EC2 nodes automatically
  HPA           — Scales pods automatically
  Prometheus    — Metrics collection
  Grafana       — Dashboards + alerts
  Loki          — Log aggregation
  Slack         — Pipeline notifications
  NetworkPolicy — Pod-to-pod security

================================================================================
FULL PIPELINE FLOW
================================================================================

  YOUR LAPTOP
      │ git push
      ▼
  GITHUB
      │ GitHub Actions triggers Jenkins
      ▼
  JENKINS (EC2 :8080)
      ├── Checkout
      ├── Build + Test (mvn verify)
      ├── OWASP Dependency Check
      ├── SonarQube Analysis ──────────────────→ SonarQube (:9001)
      ├── Quality Gate (HARD STOP if fails) ←──
      ├── Package JAR → Upload ────────────────→ Nexus (:8082)
      ├── Docker Build
      ├── Trivy Scan (CRITICAL CVE = fail)
      ├── Push image ──────────────────────────→ AWS ECR
      └── Update image tag in Git (values.yaml)
              │
              ▼ ArgoCD detects Git change
      ARGOCD (EKS)
          ├── DEV     → auto deploy → Argo Rollouts canary
          ├── STAGING → auto deploy → canary + Prometheus check
          └── PROD    → MANUAL APPROVE → canary 20% → 50% → 100%
              │
              ▼
      EKS CLUSTER (paystream-cluster)
          ├── Istio service mesh (mTLS between all services)
          ├── External Secrets (AWS Secrets Manager)
          ├── HPA (pod autoscaling)
          ├── Cluster Autoscaler (node autoscaling)
          ├── Network Policies (pod isolation)
          ├── PodDisruptionBudget (zero downtime)
          └── Prometheus + Grafana + Loki (monitoring)

  PayStream services (infrastructure/ecr.tf) are purely additive and safe

PHASE 1 — TERRAFORM (Create All AWS Infrastructure)
================================================================================

  ESTIMATED TIME: 20 minutes

  --- Step 1.1: Install Terraform on LOCAL machine ---

    Windows:
      Download from: https://developer.hashicorp.com/terraform/install
      Extract terraform.exe → add folder to Windows PATH

    Verify:
      terraform --version

  --- Step 1.2: Configure AWS CLI on LOCAL machine ---

    aws configure
      AWS Access Key ID:     <your key>
      AWS Secret Access Key: <your secret>
      Default region:        ap-south-1
      Default output format: json

    Verify:
      aws sts get-caller-identity
      (shows your account ID — confirms credentials work)

  --- Step 1.3: Create S3 bucket + DynamoDB for Terraform state ---

    Run ONCE before terraform init:

    aws s3 mb s3://paystream-terraform-state --region ap-south-1

    aws dynamodb create-table \
      --table-name paystream-terraform-lock \
      --attribute-definitions AttributeName=LockID,AttributeType=S \
      --key-schema AttributeName=LockID,KeyType=HASH \
      --billing-mode PAY_PER_REQUEST \
      --region ap-south-1

  --- Step 1.4: Create EC2 Key Pair ---

    aws ec2 create-key-pair \
      --key-name paystream-key \
      --region ap-south-1 \
      --query 'KeyMaterial' \
      --output text > paystream-key.pem

    Windows PuTTY users:
      Open PuTTYgen → Load paystream-key.pem → Save private key → paystream-key.ppk

  --- Step 1.5: Run Terraform ---

    cd backend/infrastructure

    terraform init
    terraform plan        ← review what will be created
    terraform apply       ← type 'yes' when prompted

    What Terraform creates:
      ✅ VPC + public/private subnets + NAT Gateway
      ✅ Security Groups
      ✅ EC2 instance (Jenkins server) with auto-bootstrap script
      ✅ Elastic IP for Jenkins
      ✅ EKS cluster (paystream-cluster) + worker nodes
      ✅ ECR repositories — product-service PLUS one per PayStream service
         (config-server, discovery-server, api-gateway, auth-service,
          customer-service, account-service, neft-service, rtgs-service,
          imps-service, upi-service, transaction-service,
          fraud-detection-service, notification-service, audit-service)
      ✅ IAM roles (Jenkins, EKS cluster, EKS nodes, autoscaler)

  --- Step 1.6: Save Terraform outputs ---

    terraform output

    SAVE THESE VALUES — needed in later steps:
      jenkins_public_ip            = "XX.XX.XX.XX"
      eks_cluster_name             = "paystream-cluster"
      ecr_repository_url           = "123456789.dkr.ecr.ap-south-1.amazonaws.com/product-service"
      paystream_ecr_repository_urls = { account-service = "...", neft-service = "...", ... }
      kubeconfig_command            = "aws eks update-kubeconfig ..."

PHASE 6 — EKS CLUSTER SETUP
================================================================================

  ESTIMATED TIME: 30 minutes
  NOTE: All commands run on EC2 via PuTTY

  --- Step 6.1: Configure kubectl ---

    Run the command from terraform output:
    aws eks update-kubeconfig --region ap-south-1 --name paystream-cluster

    Verify:
    kubectl get nodes
    (should show 2 nodes as Ready)

  --- Step 6.2: Create namespaces ---

    kubectl create namespace paystream
    kubectl create namespace paystream-dev
    kubectl create namespace paystream-staging
    kubectl create namespace paystream-prod
    kubectl create namespace monitoring
    kubectl create namespace argocd
    kubectl create namespace istio-system

  --- Step 6.3: Apply RBAC + quotas ---

    cd ~/paystream-banking-platform
    kubectl apply -f k8s/rbac/jenkins-rbac.yaml
    kubectl apply -f k8s/quota/namespace-dev.yaml -n paystream-dev
    kubectl apply -f k8s/quota/namespace-staging.yaml -n paystream-staging
    kubectl apply -f k8s/quota/namespace-prod.yaml -n paystream-prod

  --- Step 6.4: Install AWS Load Balancer Controller ---

    curl -O https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.7.0/docs/install/iam_policy.json

    aws iam create-policy \
      --policy-name AWSLoadBalancerControllerIAMPolicy \
      --policy-document file://iam_policy.json

    helm repo add eks https://aws.github.io/eks-charts
    helm repo update

    helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
      --namespace kube-system \
      --set clusterName=paystream-cluster \
      --set serviceAccount.create=true \
      --set serviceAccount.name=aws-load-balancer-controller

    Verify:
    kubectl get deployment aws-load-balancer-controller -n kube-system

  --- Step 6.5: Install Istio Service Mesh ---

    curl -L https://istio.io/downloadIstio | sh -
    cd istio-*/
    export PATH=$PWD/bin:$PATH
    cd ~

    istioctl install --set profile=demo -y

    kubectl label namespace paystream-prod istio-injection=enabled

    kubectl apply -f ~/paystream-banking-platform/k8s/istio/ -n paystream-prod

    Verify:
    kubectl get pods -n istio-system
    (all pods should be Running)

    NOTE: k8s/istio/destination-rule.yaml and virtual-service.yaml ship as a
    representative template for account-service only. Copy + adapt
    (name/host swapped) for the other 13 services as you bring them under
    the mesh.

  --- Step 6.6: Install ArgoCD ---

    kubectl apply -n argocd \
      -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

    Wait for ArgoCD to be ready:
    kubectl wait --for=condition=available deployment/argocd-server \
      --namespace argocd --timeout=180s

    Get ArgoCD admin password:
    kubectl -n argocd get secret argocd-initial-admin-secret \
      -o jsonpath="{.data.password}" | base64 -d && echo
    COPY THIS PASSWORD

    Expose ArgoCD UI (run in background):
    kubectl port-forward svc/argocd-server -n argocd 8083:443 &

    Open: https://localhost:8083
    OR: Access from your local machine using SSH tunnel:
      SSH tunnel: ssh -L 8083:localhost:8083 ubuntu@<EC2-IP> -i paystream-key.pem
      Then open: https://localhost:8083
    Login: admin / <password from above>

  --- Step 6.7: Install Argo Rollouts ---

    kubectl create namespace argo-rollouts

    kubectl apply -n argo-rollouts \
      -f https://github.com/argoproj/argo-rollouts/releases/latest/download/install.yaml

    Install kubectl plugin:
    curl -LO https://github.com/argoproj/argo-rollouts/releases/latest/download/kubectl-argo-rollouts-linux-amd64
    chmod +x kubectl-argo-rollouts-linux-amd64
    sudo mv kubectl-argo-rollouts-linux-amd64 /usr/local/bin/kubectl-argo-rollouts

    Verify:
    kubectl get pods -n argo-rollouts

  --- Step 6.8: Install Cluster Autoscaler ---

    kubectl apply -f ~/paystream-banking-platform/k8s/cluster-autoscaler/cluster-autoscaler.yaml

    Verify:
    kubectl get pods -n kube-system | grep cluster-autoscaler

  --- Step 6.9: Install External Secrets Operator ---

    helm repo add external-secrets https://charts.external-secrets.io
    helm repo update

    helm install external-secrets external-secrets/external-secrets \
      --namespace external-secrets \
      --create-namespace

    Verify:
    kubectl get pods -n external-secrets

  --- Step 6.10: Install Monitoring Stack ---

    helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
    helm repo add grafana https://grafana.github.io/helm-charts
    helm repo update

    # Prometheus + Grafana + Alertmanager
    helm install prometheus-stack prometheus-community/kube-prometheus-stack \
      --namespace monitoring \
      --set grafana.adminPassword=Admin@123 \
      --set prometheus.prometheusSpec.retention=7d \
      --set alertmanager.enabled=true

      --namespace monitoring \
      --set promtail.enabled=true \
      --set loki.persistence.enabled=true \
      --set loki.persistence.size=10Gi

    Verify:
    kubectl get pods -n monitoring
    (wait until all pods are Running — takes 3-5 minutes)

WHAT EACH TOOL DOES (FOR INTERVIEW)
================================================================================

  Jenkins          → CI server. Builds, tests, scans, pushes image to ECR.
                     Does NOT deploy — that is ArgoCD's job.

  SonarQube        → Scans Java code for bugs, vulnerabilities, code smells,
                     test coverage. Pipeline STOPS if quality gate fails.

  OWASP            → Scans Maven dependencies (Spring, Kafka libs) against
                     known CVE database. Fails on HIGH/CRITICAL CVEs.

  Nexus            → Stores versioned JAR files. Every build = one traceable
                     artifact. Teams can download any past version.

  Trivy            → Scans Docker image layers for OS and library CVEs.
                     Fails pipeline if CRITICAL vulnerability found.

  AWS ECR          → Private Docker registry on AWS. Stores all image versions.
                     Has built-in scan-on-push feature.

  Terraform        → Creates ALL AWS infrastructure as code. EC2, EKS, VPC,
                     ECR, IAM roles — everything in .tf files, tracked in Git.

  Helm             → Kubernetes package manager. One chart, three environments
                     (dev/staging/prod) with different values files.

  ArgoCD           → GitOps CD tool. Watches Git repo for changes.
                     When image tag changes → auto deploys to DEV+STAGING.
                     PROD requires manual approval click.

  Argo Rollouts    → Canary deployment. Routes 20% traffic to new version,
                     waits, checks Prometheus metrics, then 50%, then 100%.
                     Auto rollback if error rate exceeds threshold.

  Istio            → Service mesh. Encrypts all pod-to-pod traffic (mTLS).
                     Also handles retries, timeouts, circuit breaking at
                     infrastructure level (not application code).

  External Secrets → Pulls secrets from AWS Secrets Manager into K8s Secrets.
                     Refreshes every hour. No plaintext secrets in Git.

  Cluster CA       → Watches pending pods. If pods can't schedule due to
                     insufficient nodes → adds new EC2 nodes automatically.

  HPA              → Watches CPU/Memory of pods. Scales pods 2 → 10.
                     Works WITH Cluster Autoscaler (CA adds nodes when needed).

  Network Policy   → Firewall rules for pods. account-service (representative
                     template — see k8s/network-policy/) can ONLY talk to:
                     api-gateway, neft/rtgs/imps/upi-service, postgres, kafka,
                     discovery-server, config-server.

  PDB              → Guarantees minimum 1 pod always running during node
                     drain, upgrades, or maintenance windows.

  Prometheus       → Scrapes metrics from all pods every 15 seconds.
                     Stores time-series data for querying.

  Grafana          → Dashboards on top of Prometheus + Loki data.
                     Shows CPU, memory, request rate, error rate, latency.

  Loki             → Aggregates logs from all pods. Query with LogQL.
                     Integrated into Grafana as data source.

TROUBLESHOOTING
================================================================================

  Jenkins job not triggering:
    → Check GitHub secrets JENKINS_URL, JENKINS_USER, JENKINS_API_TOKEN
    → Check Jenkins job token matches JENKINS_JOB_TOKEN
    → Check GitHub Actions tab for errors

  SonarQube quality gate failing:
    → Open SonarQube → project → see exact failing conditions
    → Check test coverage (run: mvn verify with jacoco)

  ECR push failing:
    → Check aws-credentials in Jenkins
    → Verify IAM user has AmazonEC2ContainerRegistryFullAccess policy

  ArgoCD not syncing:
    → Check repo connection in ArgoCD Settings → Repositories
    → Check the relevant helm/paystream-service/values/<service>.yaml has
      correct image.repository and image.tag
    → kubectl logs -n argocd deploy/argocd-application-controller
    → kubectl logs -n argocd deploy/argocd-applicationset-controller
      (ApplicationSet-specific — generates the per-service Applications)

  Pods not starting in EKS:
    → kubectl describe pod <pod-name> -n paystream-prod
    → kubectl logs <pod-name> -n paystream-prod
    → Check External Secret synced: kubectl get externalsecret -n paystream-prod

  No external URL (ingress ADDRESS empty):
    → kubectl get pods -n kube-system | grep aws-load-balancer
    → Check ALB controller is running
    → kubectl logs -n kube-system deploy/aws-load-balancer-controller
